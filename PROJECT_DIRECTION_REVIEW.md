## Codex And Dot For Maximum Impact

Use one integration owner, but bounded coherent outcomes rather than permanent
persona chats. Codex handles source exploration, repair, deterministic/browser
checks and independent review. Separate writers use worktrees with baseline SHA,
allowed files, acceptance and stopping conditions. Parallelize independent
readiness work, not several agents tuning the same paths or shared dist output.

Dot owns continuity: decision ledger, dependencies, stale evidence, release-scope
drift and the next ready packet. Recent stewardship summaries show read-only
repo checks; they do not establish code implementation or access to every lead
turn. Use repository packets as the shared record when thread access is absent.
Do not repeatedly emit unchanged status. Surface a decision, completion, failure
or meaningful drift. Do not create a competing editing owner or deploy.

project-wide chats and unreliable scheduling. Dot can coordinate background work
and continue identified local tasks on its connected computer. Connection,
